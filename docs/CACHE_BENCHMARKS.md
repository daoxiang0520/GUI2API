# 缓存更新的验证与速度范围

测试日期：2026-10-26。下列数字是本机 GUI2API 热态工具操作的中位数，不包括模型推理或 DSH 调度。首轮初始化另列，不能把局部调用的倍率当成整个 Agent 的倍率。

## 自建窗口与本地网页

每组 12 次。UIA3、MSAA、Win32 是同一自建 WinForms 窗口的不同通道；DOM 是独立无头 Chromium 中的本地网页。测试不发送系统键鼠输入，fixture 的写入与按钮计数均与请求数一致。

| 通道 | 重新绑定（ms） | 写值并校验（ms） | 连续目录调用（ms） |
|---|---:|---:|---:|
| uia3 | 527.7 → 23.1 | 663.1 → 43.6 | 547.4 → 41.3 |
| msaa | 新版 167.0 | 新版 204.5 | 新版 227.8 |
| win32 | 58.5 → 24.7 | 82.8 → 37.3 | 93.1 → 39.5 |
| dom | 137.6 → 74.5 | 253.8 → 158.4 | 215.2 → 144.5 |

旧 MSAA 完整测例在后续阶段发生引用失效，未用于计算倍率。新版四个通道均完成测试。UIA3 和 Win32 整轮整树扫描从 36 次降为 2 次；三组后续热态操作均为零次整树扫描。

## QQ 当前页面的只读实测

通过原生 MSAA 通道读取现有 QQ 当前页面。混合通道发现 809 个节点；选定 MSAA 后为 798 个节点，包括 45 个 Button、2 个 Edit。发送、表情、文件标签各观察到一个对应按钮。这些是界面标签证据，没有验证按钮的业务动作。

| 路径 | 样本数 | 中位耗时 | 整树扫描次数 |
|---|---:|---:|---:|
| 整树重查 | 3 | 963.9 ms | 3 |
| 搜索框缓存重绑 | 8 | 96.5 ms | 0 |
| 表情按钮缓存重绑 | 8 | 104.0 ms | 0 |
| 已有绑定读取按钮标签 | 8 | 2.7 ms | 0 |

一次初始控件发现约 5.37 秒，另有 worker 启动开销。16 次缓存重绑均返回 resolved，8 次标签读取通过。这里比较的是不同读取路径，不是旧版/新版完成同一个 QQ 发消息任务的严格 A/B 测试。

QQ 曾在最小化/刚显示时仅返回 23 个外壳节点；不能把外壳的低延迟冒充聊天控件性能，也未证明后续树变完整的唯一原因。当前只验证已实例化页面，未展开的菜单和未加载的记录仍可能不可见。

QQ 测试未输入、未点击业务按钮、未发送消息、未切换聊天、未注入运行时。为了观察现有窗口，临时使用非激活显示并恢复最小化；未请求切换前台。

## 可复现与限制

自建测试脚本和命令见 [CACHE.md](../CACHE.md)。原始本机报告包含会话、窗口、进程或路径信息，不纳入公开仓库；这里只发布聚合计时和验证范围。后台负载会影响绝对耗时。

缓存命中仍读取原始目标，失效后重新观察；输入焦点、遮挡和上下文 guard 不使用缓存代替现场检查。完整回归和独立目录检查见 [VALIDATION.md](VALIDATION.md) 及根目录 PUBLICATION.json。
